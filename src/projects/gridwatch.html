Gridwatch

Event-driven outage map enabling live updates, community reporting, and rapid visibility into electricity disruptions at scale.

01 — System Flow

User reports outage → Location captured → Stored in database → Map updates in real-time → Other users view outage zones

02 — Database Design

reports (id, user_id, location, status, timestamp) users (id, email)

Designed to separate user actions (inspections) from decisions (approvals), allowing flexible workflows and future automation.

03 — Backend Logic

POST /api/outages/report → submit outage

GET /api/outages → fetch active outages

PATCH /api/outages/:id → update status

GET /api/zones → aggregated grid health data

Backend handles state transitions between user actions and landlord decisions, ensuring consistent data flow across the system.

04 — Design Decisions

System prioritizes user-reported data before external validation

Aggregation layer prevents duplicate outage reports from cluttering the map

Zone-based structure allows scaling from city → national grid view
