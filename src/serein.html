Guests can book without an account. After payment, they may optionally create an account with the same email to manage cancel/reschedule under a 2-hour cutoff and a max of 3 reschedules.

02 — Customer Surface

→ Upfront Paystack payment

→ Account auth + password reset

→ Cancel / reschedule with policy rules

→ Confirmation emails (Resend)

03 — Admin Operations

→ Allowlist-gated admin login

→ Bookings dashboard (search / filter / calendar)

→ Whole-day + time-range blocked slots

→ Sunday closure via business settings

→ Services CRUD (safe deactivate)

→ Paid revenue: today / week / month / all-time

04 — Backend Logic

POST /api/... — create booking + initiate Paystack
POST /api/.../verify — server-side payment verification
POST /api/.../webhook — Paystack HMAC webhook (idempotent confirm)
Admin writes via service-role · Customer booking reads via RLS (email-scoped)
Dual cookie namespaces: customer-auth vs admin — isolated sessions

Payment confirmation is shared between the verify route and webhook so retries and race conditions do not double-confirm a booking.

05 — Engineering Focus

Slot engine → opening hours, duration, existing bookings, blocked slots, closed days, past-slot rejection

Double-booking guard → pre-insert check + post-insert re-check with rollback

Timezone → Africa/Lagos across availability, cutoffs, and revenue windows

Auth → allowlisted admins; customer sessions never share admin cookies

06 — Design Decisions

Payment is required before confirmation so the calendar only fills with paid demand. Guest checkout removes signup friction; account creation stays optional and post-booking.

Admin auth is allowlist-gated and cookie-isolated from customer auth — a role claim alone is not enough to reach operations tools.

Cancel/reschedule rules (2-hour cutoff, max 3 reschedules) are shown in the UI and emails so policy is enforced where customers already look.

07 — System Insight

The hard part was not the booking form — it was keeping availability, payments, and operations consistent under concurrency. Overlap-aware slots, idempotent payment confirmation, and Lagos timezone discipline keep the product trustworthy for both guests and staff.
