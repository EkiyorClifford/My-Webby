01 — Outcome / Role

Built a property rental platform that lets landlords and tenants interact directly through structured workflows — browse, request inspection, approve — without agent middlemen slowing every step.

Owned the full stack: public listings UI, auth, inspection request flow, landlord dashboard actions, PostgreSQL schema, and REST API.

02 — Problem

Renting often depends on agents and informal back-and-forth. Landlords need control over who visits; tenants need a clear path from discovery to inspection without opaque handoffs.

04 — What I Built

  • Public home + property browse with filtering
  • User registration / login and role-aware access
  • Inspection request flow from tenant to landlord
  • Landlord dashboard to review, approve, or reject requests
  • PostgreSQL-backed data model separating actions from decisions

05 — Key Decisions

Inspection before booking. Direct booking was skipped in favor of an inspection layer — validates intent, reduces landlord risk, and leaves room for payments or scheduling later.

Separate actions from decisions. Inspections (user requests) and approvals (landlord outcomes) stay distinct so workflows stay flexible and automatable.

Explicit status transitions. pending → approved / rejected keeps both sides aligned and blocks conflicting actions.

06 — Engineering Notes

users · properties · inspections · approvals
POST /register · POST /login · GET /properties

07 — Result

A clear landlord–tenant loop without intermediaries: discovery → inspection request → decision. The core challenge was balancing user freedom with landlord control — structured workflows keep both sides aligned.
