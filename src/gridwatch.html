GridWatch

status: in progress

Outage tracking concept for regions without reliable real-time grid visibility. User reports feed a map so disruptions show up where people actually are.

Node.js Leaflet JavaScript
Preview · concept
UI screenshots and live demo coming as the build matures

01. Outcome / Role

Designing a crowd-reported outage map for regions without reliable real-time grid visibility, so people can see disruptions where they actually are, not wait on delayed provider updates.

Status: in progress. System design and API shape are drafted; UI screenshots and a live demo will land with the first usable vertical slice. Solo concept and planned build.

02. Problem

In many regions there is no reliable, real-time view of power outages. People fall back on guesswork, social media, or delayed updates from providers.

03. System Flow

1 User reports outage
→
2 Capture location
→
3 Store + aggregate
→
4 Show on map

04. What I’m Building

  • Report flow with geolocation capture
  • Map view of active outages (Leaflet)
  • Aggregation so nearby reports don’t spam the map
  • Zone model for neighborhood → city scale views
  • API for report, list, update, and zones

05. Key Decisions

Crowd reports first. User signals beat waiting on official feeds when the goal is immediate local visibility.

Aggregate nearby pins. Keep the map readable instead of littered with duplicate reports for the same street.

Zone model early. Neighborhood → city scaling without a rewrite; external grid feeds can plug in later.

06. Engineering Notes

reports → id, user_id, location, status, timestamp

users → id, email · zones planned for aggregation

POST /api/outages/report · GET /api/outages · PATCH /api/outages/:id · GET /api/zones
