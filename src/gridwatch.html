GridWatch

status: in progress

Outage tracking concept for regions without reliable real-time grid visibility — user reports feed a map so disruptions show up where people actually are.

Node.js Leaflet JavaScript
Preview — concept
UI screenshots and live demo coming as the build matures

01 — Problem

In many regions, there is no reliable, real-time visibility into power outages. People rely on guesswork, social media, or delayed updates from providers.

02 — System Flow

1 User reports outage
→
2 Capture location
→
3 Store + aggregate
→
4 Show on map

03 — Data Model

reports → id, user_id, location, status, timestamp

users → id, email

// zones planned for neighborhood → city scale aggregation

User reports are the primary signal first; external grid feeds can plug in later without rewriting the core flow.

04 — API Shape

POST /api/outages/report
GET /api/outages
PATCH /api/outages/:id
GET /api/zones
// future: WebSocket fan-out for live map updates

05 — Design Decisions

Crowd-reported outages beat waiting on official feeds when the goal is immediate local visibility.

Nearby reports should aggregate so the map stays readable instead of littered with duplicate pins.

A zone model keeps the path open from neighborhood coverage to city-wide views without a rewrite.
